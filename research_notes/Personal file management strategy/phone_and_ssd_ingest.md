## 1. QNAP's own iOS apps (Qfile Pro / QuMagie Mobile): does background auto-upload actually work, what do they produce, known complaints

### Takeaway
Both QNAP apps do offer camera-roll auto-upload, but background execution on iOS is gated by Apple: it only fires on a significant location change (location permission set to "Always") or when iOS decides to run a short background task, and QNAP's own FAQ calls this an iOS limitation. Users report that uploads stop after phone/NAS updates and need the task re-created; QuMagie Mobile can upload original HEIC and the Live Photo video part, while Qfile Pro's folder/name structure is less documented and QNAP advises against its "use original filename" option because of name collisions.

### Cited Findings
- Qfile Pro (iOS) auto-upload setup: open the File Transfer screen, tap Auto Upload Settings, choose a destination folder on the NAS, then configure device/upload rules. General Settings include: run transfers in the background "when your device's location changes"; "only transfers files when the mobile device is connected to a power source"; and use cellular when Wi-Fi is unavailable — [QNAP docs: Configuring automatic file uploads (iOS)](https://docs.qnap.com/application/qfile-pro/4.x/en-us/configuring-automatic-file-uploads-ios-20862909.html)
- Upload rules in Qfile Pro: "Scan and upload" compares file names in the destination folder and uploads files not found there (scan performed once; new Camera Roll files afterwards are uploaded automatically); "Upload all"; "Upload from" a chosen date — [QNAP docs: Configuring automatic file uploads (iOS)](https://docs.qnap.com/application/qfile-pro/4.x/en-us/configuring-automatic-file-uploads-ios-20862909.html)
- Qfile Pro iOS has a "Use original filename" setting, and release notes mention a fix for auto upload with "Creation Time" file naming producing incorrect names/paths under some region/language/time-format settings — [QNAP docs: Uploading files and folders (iOS)](https://docs.qnap.com/application/qfile-pro/4.x/en-us/uploading-files-and-folders-ios-B6EF3FB6.html); [Qfile Pro App Store listing](https://apps.apple.com/us/app/-/id526330408)
- Requirements: iOS 15 or later; NAS running QTS 4.0+ or QuTS hero 4.5.0+. Qfile Pro does not support automatic uploads to QES and QNE devices — [QNAP docs: Automatic file uploads](https://docs.qnap.com/application/qfile-pro/4.x/en-us/automatic-file-uploads-270267D6.html)
- App Store listing warning: "To ensure that Qfile Pro can continually provide this background service, you must allow the location service - please note that this may noticeably decrease battery life." — [Qfile Pro App Store listing](https://apps.apple.com/us/app/-/id526330408)
- QNAP FAQ on why Qfile/QuMagie/Qsync need location: iOS decides when to launch an app's background tasks and provides up to 30 seconds of background runtime; background uploads require location access set to "Always" and a significant position change (about 500 m or more). FAQ last modified January 2023. A user in that FAQ reported tasks still not running in the background even with Always location — [QNAP FAQ cid=1494](https://www.qnap.com/en-me/how-to/faq/con_show.php?cid=1494); [QNAP FAQ: why do those apps need my phone's location](https://www.qnap.com/pl-pl/how-to/faq/article/ios-qfilequmagieqsync-pro-why-do-those-apps-need-to-use-my-phones-location)
- QNAP FAQ "What can I do if Qfile fails to automatically upload files?": most common cause is wrong username/password (re-select the NAS to re-login); otherwise delete and recreate the auto-upload task (Qfile Pro 4.1.0+: Transfer tab > Auto Upload Tasks > Delete File Upload Settings); iOS needs access to all photos — [QNAP FAQ cid=2815](https://www.qnap.com/en-as/how-to/faq/con_show.php?cid=2815)
- QNAP community (Dec 2025): a TS-253D owner reported auto upload stopped after a firmware update/reboot; logging out/in did not help, reinstalling the app did; "it clearly does not survive a reboot of the phone"; a reply noted the problem is "exacerbated by OS updates and automated permission changes" — [QNAP community: help me to understand qfile pro](https://community.qnap.com/t/help-me-to-understand-qfile-pro/4617)
- QNAP community thread "QuMagie vs. Qfile Pro for photo auto-backup": one user runs Qfile on phones uploading to a per-user staging folder, then a scheduled Qfiling task sorts into a single photos folder and skips duplicates; moving a photo to an album on the phone can cause the app to upload it again and create duplicates on the NAS — [QNAP community thread 2353](https://community.qnap.com/t/qumagie-vs-qfile-pro-for-photo-auto-backup/2353)
- QNAP's own positioning: Qfile Pro is a general file manager that can upload to any NAS folder with no face recognition/album creation; QuMagie is for photo/video libraries with AI organization; QNAP recommends QuMagie for photo management and Qfile Pro if you want uploads outside the QuMagie library — [QNAP FAQ cid=3411](https://www.qnap.com.cn/zh-cn/how-to/faq/con_show.php?cid=3411)
- QuMagie Mobile backup options: folder structure can mirror the phone's source folders, use subfolders named after albums, or one combined folder; Live Photo setting "Upload photo only" or "Upload photo and video"; HEIC handling "JPEG" (convert, upload converted only), "HEIC" (upload originals untouched), or "HEIC & JPEG" (both); duplicates can be skipped or renamed; QNAP recommends disabling the original-filename option because "duplicate file name conflicts may occur under certain circumstances" — [QNAP FAQ: How do I back up photos and videos with QuMagie Mobile? (cid=3098)](https://www.qnap.com/en/how-to/faq/con_show.php?cid=3098)
- If Live Photos show as stills in QuMagie, check "Upload photo and video" in auto upload settings and install the latest QuMagie on the NAS; a Live Photo is a still plus a ~3 s video sharing the same filename, and if the video codec (often HEVC from iOS defaults) is unsupported by the NAS the photo is not recognized as a Live Photo — [QNAP FAQ cid=2425](https://www.qnap.com/en/how-to/faq/con_show.php?cid=2425)
- QuMagie iOS App Store listing shows 2.0/5 from 71 ratings (snapshot undated); recent release notes fix "file upload task failures after upgrading QuMagie on the NAS" and "video files could become corrupted after retrying failed upload tasks"; latest version requires iOS 26 or later — [QuMagie App Store listing](https://apps.apple.com/app/id1453939594)
- QNAP forum thread on automatic iOS photo backup over Wi-Fi: one commenter blames QNAP's apps (including QuMagie) for a poor experience; another says "QFile does that, except the different folders" and has used it for a long time — [QNAP forum viewtopic p=819792](https://rss.qnap.com/viewtopic.php?f=178&p=819792)
- Third-party alternative "Photos Backup for QNAP" (Sonar Workshop, built on QNAP's official API): listing says backups "continue in the background (iOS 26+)" with "smart idle-time automatic backup," warns "third-party apps have a limited background time. Please do your first backup in foreground"; Monthly Unlock $2.99 / Lifetime Unlock $39.99; 4.7 stars from ~348 ratings; an automated review-sentiment site scores it ~68% negative; a user reported it stopped working after enabling QNAP 2FA — [App Store id1182636054](https://apps.apple.com/us/app/-/id1182636054); [justuseapp reviews](https://justuseapp.com/en/app/1182636054/photo-backup-for-qnap/reviews)
- Another third-party app "QPhoto Backup" claims auto backup to QNAP "in the background without user action" — [App Store id6448807750](https://apps.apple.com/us/app/-/id6448807750)
- Qfile Pro added "Rename files during manual upload" on Android and iOS (2025 community announcement) — manual uploads only — [QNAP community 5487](https://community.qnap.com/t/qfile-pro-update-rename-files-during-manual-upload-now-available-on-android-ios/5487)

### Inferences
- The realistic model for any QNAP app on iOS: foreground upload is reliable; background upload is opportunistic (location-change or short iOS background slots) and should be treated as "catch-up when you open the app," not a guaranteed nightly sync.
- The forum pattern "upload to a staging folder, then let Qfiling (NAS-side) sort into dated folders and dedupe" is the documented way to get clean organization from Qfile, since the app itself does not advertise date-based subfolder templates.
- QuMagie Mobile is the only QNAP app whose docs explicitly describe HEIC-original and Live-Photo-video upload options; Qfile Pro's treatment of Live Photo MOV parts and ProRAW is not documented in the excerpts I could reach.

### Gaps
- Could not read the full Qfile Pro iOS auto-upload page (proxy blocked), so the exact folder/naming output (e.g., whether it creates a per-device folder, whether "Creation Time" naming creates date subfolders) is unverified.
- No source found stating whether Qfile Pro or QuMagie Mobile upload ProRAW (DNG) or ProRes originals; no Reddit r/qnap threads surfaced in search results (QNAP community forum threads were found instead).
- No independent 2025-2026 test of QNAP app background reliability on iOS 26.

## 2. PhotoSync (touchbyte): targets, Autotransfer, folder/file templates, metadata, Live Photos, cost, de-facto status

### Takeaway
PhotoSync is a one-time-purchase (Pro) iOS app that transfers full-resolution originals (HEIC, RAW, Live Photo HEIC+MOV pairs) to SMB/FTP/WebDAV/SFTP NAS targets with per-target folder-by-date/album templates and custom file names; its Autotransfer runs only when iOS wakes it (arrival at a saved location, or a scheduled time while charging with the app still in the app switcher), so it is "automatic" but not continuous. Among NAS users in forums it is the most frequently named third-party option, but I found no survey-style evidence to call it the de-facto standard.

### Cited Findings
- Targets: "Securely backup photos & videos to NAS devices, personal cloud and wireless portable hard drives over FTP, SMB, WebDAV and SFTP"; QNAP named among supported NAS brands; preserves EXIF/GPS metadata; "Automatically organise files into folders by recording date, media type, album name and metadata on target device. Customisable file names" — [PhotoSync App Store listing](https://apps.apple.com/app/id415850124); [photosync-app.com](https://photosync-app.com/)
- Free version limits: "Photos and videos are only transferred in low quality, and images are converted to JPEG format. These restrictions can be removed by upgrading to PhotoSync Pro"; Pro adds full-size transfers and RAW and HEIC support — [PhotoSync App Store (DE)](https://apps.apple.com/de/app/photosync-fotos-%C3%BCbertragen/id415850124); [PhotoSync: Which plan should I get](https://www.photosync-app.com/support/ios/answers/which-photosync-plan-for-ios-should-i-get)
- Pricing structure: Pro is a lifetime (one-time) purchase; Premium is available as lifetime or subscription — [PhotoSync: Pro vs Premium](https://www.photosync-app.com/support/ios/answers/what-is-the-difference-between-photosync-pro-and-premium). AlternativeTo lists one-time purchases "ranging between $6 and $25" plus subscriptions — [AlternativeTo](https://www.alternativeto.net/software/photosync/about/). An older German article (v4.3 era) listed Premium at 0.99 EUR/month or 6.99 EUR/year — [appgefahren.de](https://www.appgefahren.de/?p=280601)
- Autotransfer triggers (iOS): two options — a location trigger, or "a fixed time while the phone is on a charger." Location requires iOS location access set to "Always"; fires only when you enter a saved place from elsewhere; saved locations must be at least 200 m apart — [PhotoSync: transfer when I arrive at a location](https://www.photosync-app.com/support/ios/answers/how-do-i-automatically-transfer-photos-when-i-arrive-at-a-pre-selected-location)
- Time trigger caveat: "iOS will only trigger the start of PhotoSync from the specified time if your device is connected to the charger cable and if PhotoSync is in the list of recently used apps"; swiping the app away disables the trigger — [PhotoSync: automatically transfer once a day](https://www.photosync-app.com/support/ios/answers/how-do-i-automatically-transfer-photos-once-a-day)
- Wait-for-Wi-Fi: after waking, PhotoSync tries for 2 min 30 s to get Wi-Fi; otherwise it goes back to sleep. Logging can be enabled under Service & Support for troubleshooting — [PhotoSync: solve autotransfer problems on iOS](https://www.photosync-app.com/support/ios/answers/how-to-solve-my-autotransfer-problems-on-ios)
- Autotransfer sources: specific user or smart albums, or all user/smart albums — [PhotoSync 4.9.5 release notes](https://www.photosync-app.com/support/release-notes/photosync-4-9-5-for-ios-released)
- Live Photo format setting (4.9.5): "Apple (2 Files)" (default) writes a photo file (JPEG/HEIC) plus a MOV; "Motion Photo (JPEG)" embeds video in a JPEG (converts to JPEG + H.264); "Apple + Motion Photo" writes both — [PhotoSync 4.9.5 release notes](https://www.photosync-app.com/support/release-notes/photosync-4-9-5-for-ios-released)
- Metadata Mode: "Standard Mode" re-encodes image data when embedding metadata; "Lossless Mode" (experimental) keeps image data where possible — [PhotoSync 4.9.5 release notes](https://www.photosync-app.com/support/release-notes/photosync-4-9-5-for-ios-released)
- Version 3.2 added recreating the Photos album structure as sub-directories on the target (works for Autotransfer too) — [PhotoSync 3.2 release notes](https://www.photosync-app.com/support/release-notes/photosync-3-2-for-ios-released); 3.2.3 added an option to transfer both HEIC and converted JPEG — [PhotoSync 3.2.3 release notes](https://www.photosync-app.com/support/release-notes/photosync-3-2-3-for-ios-released)
- A bug fix noted that edited Live Photos with "Live Effect removed" did not transfer the MOV when Version was "Original" or "Original+Edited" (now fixed) — [PhotoSync 4.9.5 release notes](https://www.photosync-app.com/support/release-notes/photosync-4-9-5-for-ios-released)
- Third-party review summary: users like "reliable nightly backups"; recurring complaints include unstable connectivity requiring the app to stay open and file-name duplication handling bugs — [nascompares forum](https://ask.nascompares.com/printthread.php?tid=8228)
- Forum users pair PhotoSync with Nextcloud/NAS "for the last few years"; one noted high-quality backup is behind the paid tier — [Lemmy thread](https://lemmy.ndlug.org/post/4530)
- PhotoSync's companion/"premiumwork" page advertises "Automatically backup photos & videos in the background" — [photosync-app.com/premiumwork](https://www.photosync-app.com/premiumwork)

### Inferences
- For a NAS-first household, PhotoSync Pro's "arrive home -> upload to SMB share into {date}-templated folders" is the closest thing to zero-touch on iOS without a server-side app, provided the phone leaves and returns home (location trigger) or is charged at a fixed time with the app left in the switcher.
- Because Pro is a one-time purchase and Autotransfer is documented as part of the iOS app's support pages, the "no new subscriptions" constraint is satisfied; whether some Autotransfer triggers require Premium is not confirmed (see Gaps).

### Gaps
- Exact current Pro price in USD (App Store page blocked); exact folder-template syntax (date tokens) and rename-token list not reachable.
- No PhotoSync document found on behavior with iCloud "Optimize iPhone Storage" (whether it triggers original downloads). A different app (Photo Transfer App) documents that iOS fetches the original from iCloud on request, which is the general PhotoKit behavior — [Photo Transfer App help](https://help.phototransferapp.com/article/150-icloud-photos)
- Whether the location/time Autotransfer triggers are Pro-level or Premium-only is not stated in the pages surfaced.

## 3. Immich iOS background backup (and ingesting an existing folder tree); Nextcloud / Synology Photos / Ente comparisons

### Takeaway
Immich's iOS background backup exists but, per its own FAQ, iOS decides when background tasks run; user reports in 2025 are mixed, with many keeping the app open for bulk uploads. Immich can expose an existing folder-structured library read-only via External Libraries, but mobile uploads never go into an external library and duplicate checks are per-library, so the two paths do not merge cleanly.

### Cited Findings
- Immich FAQ "Why is background backup on iOS not working?": "On iOS (iPhone and iPad), the operating system determines if a particular app can invoke background tasks"; remedies include enabling Background App Refresh and disabling Low Power Mode — [Immich FAQ (GitHub source)](https://github.com/immich-app/immich/blob/main/docs/docs/FAQ.mdx)
- Immich FAQ: "Immich does not modify the original files"; "Immich always keeps your original files"; it deletes originals only when trash is emptied in the UI — [Immich FAQ](https://github.com/immich-app/immich/blob/main/docs/docs/FAQ.mdx)
- External libraries: "Duplicate checking only exists for upload libraries, using the file hash"; duplicate checking "is not global, but per library"; read-only libraries cannot have edits saved — [Immich FAQ](https://github.com/immich-app/immich/blob/main/docs/docs/FAQ.mdx)
- External library guides: Immich reads files in place and never moves/renames them; mount with `:ro` (e.g. `/srv/photos/archive:/mnt/media/archive:ro`); in read-only libraries Immich cannot write `.xmp` sidecars for edited metadata; "The mobile app doesn't back up into an external library; uploads always go to Immich-owned storage" — [lumadock tutorial](https://lumadock.com/tutorials/immich-external-library); [ZimaSpace: read-only external libraries](https://shop.zimaspace.com/blogs/support-tips/immich-external-libraries-read-only-sources)
- Immich mobile docs (Free Up Space section): with iCloud Photos, deleting via Free Up Space removes the photo from iCloud and other devices (two-way sync); iCloud Shared Album assets are excluded; for users who also rely on iCloud as a backup, Immich recommends using "Optimize iPhone Storage" instead — [Immich mobile-app docs (GitHub source)](https://github.com/immich-app/immich/blob/main/docs/docs/features/mobile-app.mdx)
- Immich mobile added an "ignore iCloud photos" string (PR #12788, March 2025) described as "photos that are stored on iCloud will not be uploaded to the Immich server" — [Immich repo mirror](https://ark.sudovanilla.org/Infrastructure/immich/commit/057510af0a253b4aaf606906b13a98bd554a922a)
- User reports: a Lemmy user said a release after v1.141.1 (Sept 2025) advertised "better background backups" and they had no significant issues after v2.0; others say background upload "was horrible" earlier and that "both iOS and Android like to kill background processes," so they open the app manually — [Lemmy thread](https://lemmy.manganiello.tech/post/155440/626); [scribe.disroot.org post](https://scribe.disroot.org/post/8579382)
- A troubleshooting guide (hometechops) says the background worker only starts once the app is backgrounded and the OS scheduler decides when; advises foreground uploads for first bulk import — [hometechops](https://hometechops.com/self-hosting/immich-photos-not-backing-up)
- A guide to migrating iCloud to Immich uses `icloudpd --size original` to pull full-resolution originals (not optimized copies) and `--until-found` for incremental runs, then imports to Immich — [mustafa.net, Aug 2026](https://mustafa.net/2026/08/01/how-to-move-your-icloud-photos-to-immich-with-icloudpd/)
- Immich issue #9129: iOS app fails to upload some photos, possibly due to duplicate filenames such as "FullSizeRender" — [GitHub issue 9129](https://github.com/immich-app/immich/issues/9129)
- Comparison context: a Synology ecosystem user was looking to leave for better Android app/Wi-Fi sync/sharing; Immich users describe breaking changes and the project's own "don't use as your only copy" warning — [Lemmy thread](https://lemmy.ndlug.org/post/4530)
- Nextcloud iOS auto-upload: a user reported auto-upload "changes format from heic to jpg" at upload time (dated forum post) — [Nextcloud help](https://help.nextcloud.com/t/live-heic-photos-and-iphone-app/85955)
- General Live Photo caveat for third-party uploaders: Plex's iOS client uploads only the photo portion of Live Photos (feature request); Jottacloud added Live Photo video backup in its v4.2 — [Plex forums](https://forums.plex.tv/t/support-camera-upload-for-ios-live-photos/188663.md); [Jottacloud docs](https://docs.jottacloud.com/en/articles/2338913-ios-backup-live-photos)

### Inferences
- Immich on a QNAP (via Container Station) is viable as a viewer/AI index of an existing dated folder tree (read-only external library), but as the phone ingest point it duplicates storage versus a PhotoSync/Qfile folder pipeline and needs a separate strategy to get those uploads into the dated tree.
- Any PhotoKit-based uploader (Immich, PhotoSync, QNAP apps) is subject to the same iOS background-task scheduler; differences between apps are mostly in how they trigger (location vs. BGTask) and how they recover.

### Gaps
- Immich's own mobile docs page for Backup was empty in the fetched capture, so official statements about iOS charging/Wi-Fi conditions and Live Photo upload could not be quoted.
- Found no Ente documentation or user reports on iOS background backup or Live Photo handling.
- No Synology Photos iOS backup specifics surfaced (only general ecosystem complaints).

## 4. Apple-native paths: Image Capture / Photos import, Finder, Shortcuts, iPad Files + SMB + USB-C SSD, direct iPhone-to-SSD ProRes recording, iPhone 17 era

### Takeaway
Apple's native paths are reliable but manual: Image Capture / Photos import over USB pass HEIC + MOV Live Photo pairs and originals when the iPhone's "Transfer to Mac or PC" is set to Keep Originals; Files on iPhone/iPad can mount an SMB share (SMB 2/3) and copy to a USB-C SSD; Shortcuts has no "new photo" trigger, so only polling-style automations (time/charger) are possible. iPhone 15 Pro, 16 Pro and 17 Pro can record ProRes directly to an exFAT USB-C SSD (10 Gbps cable, 220 MB/s for 4K60, 440 MB/s for 4K120), and iPhone 17 Pro adds ProRes RAW whose documentation lagged at launch.

### Cited Findings
- Apple: iPhone 17 Pro, iPhone 16 Pro and iPhone 15 Pro models can record Apple ProRes directly to an external storage device connected over USB-C — [Apple Support: About Apple ProRes on iPhone (109041)](https://support.apple.com/en-kz/109041)
- Requirements quoted from Apple's page in community/vendor sources: drive must be formatted exFAT; password-encrypted drives unsupported; "Use a USB 3 cable with speed of at least 10 Gbits per second"; minimum write 220 MB/s for 4K60 ProRes and 440 MB/s for 4K120; "You must re-format your external storage device before beginning each 4K120 ProRes recording session"; disconnect the drive to record internally again — [Apple Community: Missing iPhone 17 Pro ProRes RAW documentation (Sept 2025)](https://discussions.apple.com/thread/256134492); [Silicon Power blog](https://sp-siliconpower.com/blogs/blog-2/recording-4k-60fps-prores-on-an-iphone-using-an-external-ssd-is-fun-and-games-but-how-and-why); [AppleInsider SSD guide](https://appleinsider.com/inside/iphone-15-pro/best/the-best-ssds-for-recording-video-on-iphone-15-pro/amp/)
- An Italian guide citing Apple lists a maximum drive power draw of 4.5 W — [iPhoneItalia](https://www.iphoneitalia.com/?p=814332) (not confirmed against Apple's page)
- iPhone 17 Pro ProRes RAW: a Sept 2025 Apple Community thread says Apple had not updated its ProRes article for ProRes RAW; sources disagree on whether an external SSD is mandatory for RAW (one comparison calls it "Optional" for ProRes, "Essential" for ProRes RAW HQ; a vendor says RAW requires external storage); guides say iOS 26 plus Final Cut Camera are needed — [Apple Community 256134492](https://discussions.apple.com/thread/256134492); [iGeeksBlog: ProRes RAW on iPhone 17 Pro](https://www.igeeksblog.com/how-to-record-prores-raw-on-iphone-17-pro/)
- Image Capture / Lightroom imports: a Live Photo arrives as a .HEIC plus a .MOV, which must be imported together; iPhone Settings > Photos > Transfer to Mac or PC > "Keep Originals" prevents JPEG conversion (one user said it did not help in their case); Capture One users found importing via the Mac Photos library converted ProRAW/HEIC to JPEG, while another gets originals "using Image Capture then import to Capture One" — [Adobe Community: Live Photo video data](https://community.adobe.com/t5/lightroom-classic-discussions/lightroom-not-importing-video-data-for-all-live-photos/m-p/10730886); [Capture One community](https://support.captureone.com/hc/en-us/community/posts/18528251242525-Import-RAW-HEIC-photos-from-iPhone-into-Capture-One-23)
- Files app SMB: on iOS 13.1+ use Browse > "Connect to Server" with the share address; the server must support SMB 2.0 or higher (one user had to raise the NAS max protocol to SMB3); the share then appears under Shared and is available to any app that supports Files — [OSXDaily](https://osxdaily.com/2019/11/04/how-connect-smb-share-iphone-ipad-files-app/); [TechRepublic](https://www.techrepublic.com/article/how-to-use-the-files-app-to-connect-to-a-network-server-from-your-iphone-or-ipad/); [Visuality](https://visualitynq.com/resources/ios-with-smb-protocols/)
- iPad + external SSD: a drive plugged into the iPad appears in Files under Locations; from Photos use Share > Save to Files > pick the drive (user-reported); "The Files app does not allow you to view the Photo Library content" — [TapSmart: iPad external drives](https://www.tapsmart.com/tips-and-tricks/ipad-external-drives/); [Apple Community 252851180](https://origin-discussions2-us-dr-prz.apple.com/thread/252851180)
- iOS 26 Files app can format a connected drive as APFS, exFAT or MS-DOS — [Macwelt (early 2026)](https://www.macwelt.de/article/2548861/ssd-finder-loschen.html)
- Shortcuts: Apple's gallery example "upload to Dropbox" retrieves the most recent N photos and saves them to a destination (the reusable pattern); Shortcuts has a "charger connected" personal-automation trigger with "Run Immediately" to avoid prompts — [xray.tech on Apple Shortcuts](https://xray.tech/post/apple-shortcuts); [techtiff: charger automation](https://techtiff.substack.com/p/iphone-charger-automation)
- A forum user wanting new photos saved to a folder automatically got no working answer beyond "use Shortcuts" — [MPU talk](https://talk.macpowerusers.com/t/newb-needs-help-with-shortcuts/30614)
- QNAP Qfile on iPad can browse/move/copy files on the NAS but does not write to a USB SSD directly — [Qfile Pro App Store listing](https://apps.apple.com/us/app/-/id526330408)

### Inferences
- A Shortcuts "when charging -> Find Photos (last N by date added) -> Save File to SMB share" automation is buildable but has no dedupe state and depends on the share being reachable; it is a convenience, not a backup system.
- Direct-to-SSD ProRes recording is the one path that keeps multi-GB video out of iCloud entirely and lands it on a drive you can plug straight into the Mac/NAS.

### Gaps
- Apple's ProRes support page itself was not readable (proxy); the 220/440 MB/s, exFAT and cable requirements are quoted via secondary sources that attribute them to Apple.
- No source confirmed whether Image Capture on macOS 26 transfers ProRAW DNG and Live Photo MOV intact in all cases; Apple's own Image Capture docs were not reachable.
- No confirmed iPhone 17-specific storage/ingest capability beyond ProRes RAW and the general "ProRes to external USB-C" support statement.

## 5. The iCloud "Optimize Storage" problem: uploading originals when the phone holds only downsized copies; Mac as hub

### Takeaway
With Optimize iPhone Storage on, Apple keeps originals in iCloud and "space-saving versions" on the phone; well-behaved PhotoKit apps request the original and iOS downloads it from iCloud on demand, so uploads are full-size but slow and network-dependent. The widely recommended answer is a Mac "hub" with iCloud Photos set to "Download Originals to this Mac" (library on internal or external APFS/HFS+ SSD, never on the NAS) and an osxphotos export to the NAS.

### Cited Findings
- Apple (as quoted in community threads): "If you turn on Optimize Storage, iCloud Photos automatically manages the size of your library on your device. Your original photos and videos are stored in iCloud and space-saving versions are kept on your device"; "Your library is optimized only when you need space, starting with the photos and videos you access least"; "If you turn on Download Originals, iCloud Photos keeps your original, full-resolution photos and videos in iCloud and on your device" — [Apple Community 254682229](https://origin-discussions2-us-dr-prz.apple.com/thread/254682229); [Apple Community 255532017](https://discussions.apple.com/thread/255532017)
- On Mac the equivalent is "Optimise Mac Storage" with "Download Originals to this Mac" to restore full files — [Apple Photos User Guide (macOS 26)](https://support.apple.com/en-hk/guide/photos/optimise-storage-in-photos-on-mac-phta9b4673b4/11.0/mac/26)
- Photo Transfer App documents the PhotoKit behavior: "When you pick a photo to send, Photo Transfer asks iOS for the full original. If the original isn't on the device, iOS downloads the original from iCloud over your internet connection before returning it"; path to force local originals: Settings > [name] > iCloud > Photos > Download and Keep Originals — [Photo Transfer App help](https://help.phototransferapp.com/article/150-icloud-photos)
- Apple: a Photos library can be stored on a USB/Thunderbolt drive formatted APFS or Mac OS Extended (Journaled), not on a Time Machine disk; Apple "doesn't recommend storing photo libraries on external storage devices like SD cards and USB flash drives, or drives that are shared on a network"; if iCloud Photos is enabled the drive must be mounted before Photos opens — [Apple Support HT201517 (archived 2021 snapshot)](https://webcf.waybackmachine.org/web/20210812034547/https://support.apple.com/en-us/HT201517)
- Running Photos as a referenced library with originals on a NAS is "not a stable configuration" (user report) — [macfreak.nl](https://www.macfreak.nl/vragen-algemeen/foto-s-bibliotheek-verplaatsen-naar-nas/msg543359/)
- With "Download Originals" selected the Mac keeps full-size originals; time NAS backups after Photos has finished downloading — [Apple Community 254827407](https://discussions.apple.com/thread/254827407)
- osxphotos: photos may be missing locally due to iCloud sync, "Optimize Mac Storage," shared albums, etc.; `--download-missing` asks Photos (via AppleScript) to download them, Photos' AppleScript interface is "somewhat buggy" and Photos may crash (osxphotos restarts it); experimental `--use-photokit` must be combined with `--download-missing`; known bug: `--download-missing` downloads only the primary image of bursts — [osxphotos README](https://github.com/RhetTbull/osxphotos)
- Immich recommends "Optimize iPhone Storage" for users who rely on iCloud, and its "ignore iCloud photos" option skips iCloud-only assets — [Immich mobile docs](https://github.com/immich-app/immich/blob/main/docs/docs/features/mobile-app.mdx); [Immich repo mirror](https://ark.sudovanilla.org/Infrastructure/immich/commit/057510af0a253b4aaf606906b13a98bd554a922a)
- A Lemmy user explains that for Immich "the photos are local to the phone, not from iCloud," so backing up all of iCloud requires downloading those photos to the phone first — [communities.stormux.org](https://communities.stormux.org/post/19508/70030)
- icloudpd `--size original` downloads full-resolution originals, not optimized copies, directly from iCloud (Linux/Docker, could run on the NAS) — [mustafa.net guide](https://mustafa.net/2026/08/01/how-to-move-your-icloud-photos-to-immich-with-icloudpd/)

### Inferences
- With a 200 GB iCloud+ plan, the Mac-hub pattern needs a Mac with enough local/external SSD space for the full library plus headroom; a Mac mini or the household's largest-SSD Mac with Photos library on an external APFS SSD is the standard way to keep "Download Originals" on without filling the internal drive.
- Phone-side uploaders remain useful for same-day capture to the NAS, but the Mac hub is the only path that guarantees originals including items the phone has already optimized away.

### Gaps
- No PhotoSync, Qfile or QuMagie document states explicitly whether they call PhotoKit with "network access allowed" (i.e., trigger iCloud downloads) or fall back to the optimized copy; only the Photo Transfer App's statement and general PhotoKit behavior were found.
- The current (2026) Apple HT201517 page was not reachable; the 2021 snapshot was used.

## 6. osxphotos: exporting the Apple Photos library with people/album/keyword metadata into folder structures, and automating a family-branch split via People

### Takeaway
osxphotos (open source, Python, supports macOS 10.12 through 26.x/27.0) can export originals plus edited versions with `--directory`/`--filename` templates built from fields such as `{created.year}`, `{folder_album}`, `{album}`, `{person}` and `{keyword}`, write XMP/JSON sidecars or embed metadata with exiftool, and run incrementally with `--update`; People-based folder exports are possible via the `{person}` template field, though I could not read the template-system text that states how multi-person photos are handled.

### Cited Findings
- Compatibility: macOS 27.0 down to 10.12 listed; macOS 26.x (Tahoe) "limited testing has been done" and "OSXPhotos cannot read shared albums on macOS 26.x"; Python 3.10-3.14 — [osxphotos README](https://github.com/RhetTbull/osxphotos)
- `--directory` and `--filename` accept templates, e.g. `--directory "{created.year}/{created.month}"`; `{folder_album}` preserves the Photos folder/album path (`Folder/Subfolder/Album`); `{album}` = "Album(s) photo is contained in"; `{person}` = persons/faces in the photo; `{keyword}` = keywords — [osxphotos README](https://github.com/RhetTbull/osxphotos)
- Template helpers present in the README: `{shell_quote,TEMPLATE}`, `{strip,TEMPLATE}`, `{format:TYPE:FORMAT,TEMPLATE}`; `--keyword-template` uses the `{name,DEFAULT}` syntax (DEFAULT used when a field is empty) — [osxphotos README](https://github.com/RhetTbull/osxphotos); [oPromessa README mirror](https://github.com/oPromessa/osxphotos/blob/main/README.rst)
- Sidecars/metadata: `--sidecar` writes exiftool-compatible JSON or XMP without needing exiftool; `--sidecar-drop-ext` names them `IMG_1234.XMP`; `--exiftool` writes metadata into exported files; `--finder-tag-keywords` and `--xattr-template` write Finder tags/xattrs; `--person-keyword` adds each person's name to keywords — [osxphotos README](https://github.com/RhetTbull/osxphotos); [MacRumors thread showing `--person-keyword`](https://fcdn.macrumors.com/threads/cannot-open-photo-library-from-high-sierra-on-monterey.2415776/)
- Incremental export: `--update` uses `.osxphotos_export.db` to export only new/changed items; `--only-new`; `--ignore-signature` — [osxphotos README](https://github.com/RhetTbull/osxphotos)
- Live Photos: the MOV component is exported by default; `--skip-live` to skip — [osxphotos README](https://github.com/RhetTbull/osxphotos)
- Quick examples: `osxphotos export --export-by-date --library ~/Pictures/Photos\ Library.photoslibrary ~/Desktop/export`; `osxphotos query --keyword Kids --json`; `osxphotos persons` lists people names; `osxphotos template` interactively renders templates; `--dry-run` previews — [osxphotos README](https://github.com/RhetTbull/osxphotos); [osxphotos on PyPI](https://pypi.org/project/osxphotos/)
- Real-world example: `--directory "{folder_album,No Album}"` keeps the folder/album structure and puts un-albumed photos in "No Album"; the poster warns faces/persons cannot be preserved on re-import to Photos (names survive only as keywords) — [MacRumors thread](https://fcdn.macrumors.com/threads/cannot-open-photo-library-from-high-sierra-on-monterey.2415776/)
- osxphotos `import` can use the directory relative to the export folder as the album name on re-import — [oPromessa README mirror](https://github.com/oPromessa/osxphotos/blob/main/README.rst)
- A blog example pairs `--update` with `--download-missing` so only new/changed photos since the last export are written — [billmill notes on osxphotos](https://notes.billmill.org/computer_usage/mac_os/photos/osxphotos.html); [mjtsai: OSXPhotos Python Tool](https://mjtsai.com/blog/2022/02/25/osxphotos-python-tool)
- Apple's manual alternative: open a person in People, "Show All", File > Export — [Apple Community 255607822](https://communities.apple.com/thread/255607822)

### Inferences
- A practical "family / wife's family / mother's side" split: tag people in Photos, then either (a) run three exports each filtered by person (`osxphotos export ... --person "Name1" --person "Name2" --directory "{created.year}/{created.month}"`) into three NAS roots, or (b) a single export with `--sidecar XMP --person-keyword` and let Immich/NAS search handle people; option (a) duplicates photos containing people from multiple branches, so the exported tree should be treated as a derived view with the Photos library as the source of truth.
- Because `--update` is incremental and the Mac is the iCloud "hub," a nightly launchd job running osxphotos to the NAS share is the lowest-maintenance way to produce a dated folder tree with metadata.

### Gaps
- The README section explaining multi-valued template behavior in `--directory` (whether one photo is written to each person's folder) and the exact `--person` filter flag text were in the part of the page I could not read; verify with `osxphotos help export` and `osxphotos template`.
- Current osxphotos version number/date not confirmed (README only shows example values like 0.77.2).

## 7. Portable SSD as a transit layer: exFAT vs APFS, Hazel/rsync/ChronoSync on connect, checksum verification, Hedge/ShotPut Pro/Offload vs free tools

### Takeaway
Format a transit SSD exFAT if it must be written by the iPhone/iPad (ProRes recording requires exFAT) or shared with Windows; use APFS (optionally encrypted) for Mac-only duty. On the Mac, ChronoSync ($49.99 one-time, "Verify Copied Data" read-back check) or Hedge (xxHash + MHL; free tier limited to two simultaneous transfers; historically $99 one-time) give verified copies; rsync/rclone are free alternatives.

### Cited Findings
- exFAT recommended when a drive moves between PCs and Macs; APFS "tuned for flash storage" and default for Time Machine on Big Sur+; APFS volumes can be encrypted — [Seagate/LaCie formatting manual](https://www.seagate.com/manuals/lacie/portable-ssd/optional-formatting/); [Macwelt](https://www.macwelt.de/article/2548861/ssd-finder-loschen.html)
- iPhone external ProRes recording requires exFAT; password-encrypted drives unsupported — [Apple Community 256134492](https://discussions.apple.com/thread/256134492); [Silicon Power](https://sp-siliconpower.com/blogs/blog-2/recording-4k-60fps-prores-on-an-iphone-using-an-external-ssd-is-fun-and-games-but-how-and-why)
- iOS 26 Files can format a drive as APFS, exFAT or MS-DOS; Satechi recommends APFS for Apple-only use across iPhone/iPad/Mac and exFAT for mixed platforms — [Macwelt](https://www.macwelt.de/article/2548861/ssd-finder-loschen.html); [Satechi guide](https://satechi.com/blogs/news/maximize-your-mini-nvme-ssd-enclosure-a-quick-setup-guide)
- 2026 SSD roundups: Samsung T7 Shield (IP65, up to 1,050 MB/s), SanDisk Extreme Portable (IP65, 1,050 MB/s), Samsung T7 (AES-256) — [TheTestedHub, June 2026](https://thetestedhub.com/?p=17368); [roundup, Sept 2026](https://thegoodatheist.net/?p=34300)
- ChronoSync: $49.99 single license, "Lifetime subscription" with free updates, one Mac per license; ChronoSync Express $29.99 (Mac App Store) or via Setapp — [Econ Technologies: ChronoSync](https://www.econtechnologies.com/product/chronosync); [ChronoSync Express](https://www.econtechnologies.com/product/chronosync-express)
- ChronoSync "Verify Copied Data" (Options panel > Special File/Folder Handling): after copy, the file is read back and compared to the original; "enabling this feature roughly doubles the amount of time it takes to run a Sync Task"; separate "Validate" compares data, resource forks and metadata without modifying either target — [Econ Technologies: Verify vs Validate](https://econtechnologies.com/the-difference-between-verify-and-validate)
- Hedge: verifies via checksums and generates an MHL (media hash list) per transfer; moved from MD5 to xxHash; free version "fully featured, but limited to two simultaneous transfers"; launch pricing $99 one-time (2016, likely outdated); current version ~20.x with native Apple Silicon; TrustRadius has no current pricing listed — [Newsshooter 2016](https://www.newsshooter.com/2016/03/22/hedge-for-mac-sync-factorys-copy-and-verification-program-now-available/); [cined](https://cined.com/?p=47730); [doesitarm: Hedge](https://develop.doesitarm.com/app/hedge); [TrustRadius](https://www.trustradius.com/products/hedge/pricing)
- ShotPut Pro: aggregators list a one-time perpetual license at $149 (listing updated June 2026); 2016 press release said $129 — [Capterra](https://www.capterra.ie/software/210332/shotput-pro); [SoftwareSuggest](https://www.softwaresuggest.com/shotput-pro)
- Hazel: users report performance is now adequate for large file collections; a $0.99 third-party pack of photo-workflow Hazel rules exists — [MacDrifter](https://www.macdrifter.com/tags/mac/page/47.html); [Gumroad: photo Hazel rules](https://djvreeman.gumroad.com/l/photohazelrules)
- Ingest principle: a good ingestion app copies to more than one location and checks file integrity; a photographer's SSD setup ingests cards to one SSD and mirrors to a second every two hours with sync software — [Will Goodlet: ingestion workflows and backups](https://willgoodlet.com/digital-asset-management/ingestion-workflows-and-backups); [Skillshare project: photo backup workflow](https://www.skillshare.com/en/projects/Photo-Back-Up-workflow-Paul-Janssens/619165)

### Inferences
- A two-drive scheme fits well: one exFAT SSD dedicated to iPhone ProRes recording and iPad Files transfers, and one APFS-encrypted SSD as the Mac-side Photos-library or transit volume; Hazel (or a launchd/folder-action script) can run `rsync -a --checksum` or ChronoSync on mount to push into the NAS dated tree.
- For a household (not a film crew), ChronoSync or free rsync with a post-copy checksum compare covers verification; Hedge/ShotPut Pro are overkill unless MHL manifests are wanted.

### Gaps
- No source describing a Hazel + rsync checksum workflow specifically; current Hedge and Offload pricing in 2026 not found (search surfaced only 2016-era prices).
- Hazel's own current price was not surfaced in results.

## 8. Video-specific: where large 4K/ProRes files should live; proxy editing over SMB/10GbE vs local SSD

### Takeaway
ProRes 4K data rates (about 500 Mb/s for 422, 750 Mb/s for 422 HQ, 1.1 Gb/s for 4444 at DCI 24p) make 1GbE marginal and 10GbE workable for single-stream ProRes 422/HQ editing directly from a QNAP SMB3 share; local NVMe SSD still has far more headroom, so the common pattern is originals archived on the NAS, active projects or proxies on local SSD.

### Cited Findings
- Approximate ProRes 4K DCI 24p stream rates: 155 Mb/s (422 Proxy), 503 Mb/s (422), 754 Mb/s (422 HQ), 1,131 Mb/s (4444); 422 HQ "leaves little margin" on 1GbE — [ZimaSpace: what NAS speed for 4K editing](https://shop.zimaspace.com/es/blogs/buying-guide/what-nas-speed-do-you-need-for-4k-video-editing)
- 10GbE recommended for ProRes 422 HQ, ProRes RAW or BRAW; the network is usually the bottleneck rather than the NAS — [needtoknowit: NAS for video editors](https://needtoknowit.com.au/blog/nas-for-video-editors/)
- A 10GbE SMB test (Synology, iMac Pro era) measured ~3 Gb/s reads/writes, still slower than Thunderbolt 3 DAS and "good enough" for some 4K work — [9to5Mac](https://9to5mac.com/?p=520897)
- Apple: Final Cut Pro shared storage on a Linux NAS requires Samba 4.3.4+ with Apple compatibility modules — [Apple Support HT207128](https://support.apple.com/en-us/HT207128)
- QNAP: Final Cut Pro X 10.3+ supports SMB3 for real-time editing from the NAS; older versions needed NFS (tutorial from 2018) — [QNAP tutorial cid=180](https://www.qnap.com/en/how-to/tutorial/con_show.php?cid=180)
- Proxy workflow: FCP's "Create Proxy Media" on import; edit with proxies, switch to originals for export — [siit.co FCP proxy guide](https://siit.co/guestposts/how-to-use-proxy-workflows-in-final-cut-pro-for-smooth-editing/)
- iPhone external ProRes write minimums: 220 MB/s (4K60) and 440 MB/s (4K120) — [Apple Community 256134492](https://discussions.apple.com/thread/256134492)

### Inferences
- For the household's purposes (occasional 4K/ProRes from iPhone), keep ProRes masters on the NAS in the dated tree, generate FCP proxies locally when editing, and use the iPhone's direct-to-SSD recording for long ProRes shoots so the footage never transits iCloud or the 200 GB plan.

### Gaps
- No head-to-head benchmark of macOS 26 + current QNAP SMB3 (e.g., with QNAP's multichannel) vs local SSD for ProRes editing; the 9to5Mac numbers are from 2018-era hardware.
